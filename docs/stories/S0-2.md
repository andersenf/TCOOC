# S0-2: Architecture decisions ADR-001, ADR-003, ADR-004 and OpenAPI v0

**Epic:** Sprint 0 foundations · **Size:** L · **Owner:** Architect · **Status:** Backlog

**Dependencies:** product owner input for ADR-004: region (D-02) and account layout preference (D-03). ADR-001 and ADR-003 can start immediately.
**Blocks:** S0-3 (needs ADR-001 + ADR-004), S0-6 (needs ADR-004), S0-5 (needs OpenAPI v0 and ADR-003).

## Story
As the Developer, I want the stack, calculation-engine placement, environment/CI layout and API contract decided in writing, so that I can scaffold and deploy without guessing.

## Acceptance criteria
- Given the default stack in `CLAUDE.md`, When ADR-001 "Tech stack & AWS services" is written, Then it confirms or changes each element (frontend, API, data, ingestion, IaC, CI/CD, tests), lists at least one rejected alternative per significant trade-off, and estimates the monthly cost at low traffic against the ~20 USD/month target.
- Given `docs/02-tco-model-dk.md` v0.1, When ADR-003 "TCO calculation engine placement and config format" is written, Then it states where the engine runs (backend, frontend or shared module), how the `dk` country module is isolated, and the config file format in `src/backend/config/dk/*.json` including `source` and `validFrom` fields and how the yearly `V(a)` curve and year-dependent `T_owner(car, y)` rules are represented.
- Given the product owner's answers on region and account layout, When ADR-004 "Environments, CI/CD and IaC layout" is written, Then it decides: (a) single AWS account with `dev`/`prod` stages vs. separate accounts, (b) the EU region (`eu-north-1` or `eu-central-1`), (c) CDK stack layout (frontend/api/data), (d) how local developer access works (IAM Identity Center/SSO or named CLI profile, no long-lived keys), (e) how GitHub Actions authenticates (OIDC role per stage), and (f) the promotion path `dev` → `prod` with product owner approval for prod.
- Given ADR-004 changes cost or region, When it is proposed, Then the PM routes it to the product owner for approval before S0-6 starts (per `docs/00-factory-workflow.md`).
- Given the four endpoints `GET /cars?query=`, `GET /cars/{id}`, `POST /tco/compare`, `GET /reference/dk`, When OpenAPI v0 is published in `docs/api/openapi.yaml`, Then each endpoint has request/response schemas; `POST /tco/compare` accepts every input in the TCO model (including `condition`, `A0`, `u_el`, `L`, `r`, `N`) and returns per-year `C(y)`, the breakdown, `B(Y)`, cost per km (nullable when `K = 0`) and the break-even result (year, "none within Y", or "same purchase price"); money fields are integer øre.
- Given the validation rules in the TCO model, When OpenAPI v0 is reviewed, Then the input ranges (`Y` 1..15, `K` 0..100,000, `s_home`/`u_el` 0..1, `0 ≤ L ≤ P`, `r` 0..25%, `N` 1..10, `A0` 0..20, `new` ⇒ `A0 = 0`) are expressed in the schema or documented as server-side validation.
