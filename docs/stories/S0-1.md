# S0-1: Validate data sources (car specs, energy, fuel, taxes)

**Epic:** Sprint 0 foundations (feeds E1, E2) · **Size:** L · **Owner:** Architect · **Status:** Backlog

**Dependencies:** none. Can start on day 1, in parallel with S0-2.
**Blocks:** Product owner approval of data sources (see `status/decisions-needed.md` D-08); S0-5 (E1/E2 stories need a confirmed source per need).

## Story
As the product owner, I want every candidate data source checked for licence, access and Danish coverage, so that we only build on free data we are allowed to reuse.

## Acceptance criteria
- Given the candidate list in `docs/01-product-brief.md` §5, When the Architect finishes S0-1, Then `docs/data-sources.md` has one entry per need (car specs, EV specs, electricity prices, fuel prices, taxes, insurance/service/depreciation defaults) with: licence/terms (with URL), access method, update frequency, available fields, Danish coverage and a verdict (accept / reject / fallback).
- Given a source whose terms forbid reuse or require scraping against its terms, When it is assessed, Then it is marked **rejected** with the reason, and no story may depend on it.
- Given a need with no acceptable free source (e.g. fuel prices, insurance), When the assessment is done, Then the fallback is documented (e.g. manual monthly config update, or editable default assumptions) with who maintains it and how often.
- Given the car-spec sources (EEA CO₂ data, DMR), When they are assessed, Then the document states how a make/model/variant chosen by the user would be matched to a record, including known gaps (e.g. PHEV split consumption `c_el`/`c_fuel`, used cars with `A0` up to 20 years, which predate some EEA datasets).
- Given the tax sources (Skattestyrelsen / Motorstyrelsen), When they are assessed, Then each rate needed by `docs/02-tco-model-dk.md` (registreringsafgift, grøn ejerafgift, udligningsafgift, EV phase-in) has a source URL and a known "valid from" date, or is listed as `TODO-VERIFY`.
- Given the findings, When S0-1 is done, Then ADR-002 "Data sources & ingestion strategy" exists in `docs/adr/` with at least one rejected alternative, and the PM has raised the source choice to the product owner for approval.

## Design notes (Architect)
- ADRs / contract sections affected: ADR-002 (new); `docs/01-product-brief.md` §5 (propose changes, don't edit silently).

## Test notes (Tester)
- Oracle cases / edge cases: none directly. Tester checks that the default values the oracle will rely on (consumption real-world factor, `u_el`, `V(a)` curve points, `I`, `M`) are listed with a source or `TODO-VERIFY`.

## Out of scope
- Building the ingestion Lambda (E1/E2).
- Paid data sources or dealer price feeds.
- Company-car taxation sources (v2).
